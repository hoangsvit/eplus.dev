### GitHub tăng khả năng quản trị Copilot trong JetBrains

Ngày 10/10, GitHub công bố một bản cập nhật dành cho Copilot trong hệ sinh thái JetBrains.

Các cải tiến tập trung vào ba vấn đề thực tế.

Thứ nhất, enterprise administrators có thể cấu hình model mặc định cho những cuộc hội thoại mới.

Thứ hai, developer có thể chuyển từ IDE diagnostics sang Copilot để đề xuất sửa lỗi nhanh hơn.

Thứ ba, GitHub bổ sung tùy chọn ngăn MCP servers tự động khởi động.

Điểm thứ ba đặc biệt đáng chú ý.

Khi AI coding assistants kết nối ngày càng nhiều MCP servers, mỗi kết nối có thể mở rộng phạm vi dữ liệu và công cụ mà agent sử dụng.

Việc kiểm soát thời điểm MCP server được kích hoạt giúp developer chủ động hơn trong quản lý môi trường làm việc.

GitHub cũng xác nhận **Copilot không còn hỗ trợ JetBrains IDE 2025.1**. Developer cần sử dụng phiên bản 2025.2 trở lên.

### Amazon Bedrock bổ sung reasoning summaries

AWS công bố khả năng sử dụng tham số `reasoning.summary` với OpenAI models thông qua Amazon Bedrock Responses API.

Developer có thể yêu cầu model trả về một bản tóm tắt dễ đọc về cách tiếp cận nhiệm vụ, bên cạnh kết quả cuối cùng.

Tính năng này hữu ích khi xây:

```plaintext
Coding assistants
Analysis agents
Multi-step workflows
Automated evaluation systems
```

Reasoning summary không nên được hiểu là toàn bộ quá trình suy luận nội bộ của model.

Nó là phần tóm tắt được model cung cấp để hỗ trợ việc giải thích và đánh giá kết quả.

Đối với production AI, đây là một khả năng đáng quan tâm vì developer cần hiểu không chỉ kết quả agent trả về mà còn cách hệ thống tiếp cận vấn đề.

Đây là một ví dụ cho thấy AI đang tiến sâu hơn vào những workflow vốn yêu cầu kiến thức chuyên môn về data engineering.

### 2\. AI observability cần cả kết quả và bằng chứng

Amazon Bedrock reasoning summaries và AWS DevOps Agent Reviews cùng giải quyết một câu hỏi:

Điều này khiến behavioral monitoring và policy automation ngày càng quan trọng.

### 1\. GitHub Copilot cho JetBrains bổ sung enterprise model controls và MCP startup settings

**Công bố: 10/10/2026 — nhóm tin mới nhất theo ngày.**

GitHub công bố bản cập nhật Copilot dành cho JetBrains IDEs.

Một trong những thay đổi quan trọng là khả năng cấu hình model mặc định thông qua enterprise-managed settings.

Administrators có thể lựa chọn một model Copilot agent khả dụng làm model mặc định cho những cuộc hội thoại mới.

Developer vẫn có thể chủ động lựa chọn model khác thông qua model picker.

GitHub cũng cải thiện trải nghiệm sửa lỗi.

Developer có thể quyết định thời điểm các MCP servers được kích hoạt.

```plaintext

Automatic startup
Tool permissions
Credential access
```

Chỉ kích hoạt những công cụ cần thiết cho workflow hiện tại.

### MCP permissions sẽ trở thành một phần của developer security

Tùy chọn tắt automatic MCP server startup của GitHub Copilot là một cải tiến nhỏ nhưng có ý nghĩa.

Khi MCP servers được cấu hình, chúng có thể cung cấp quyền truy cập vào:

```plaintext
Local files
Repositories
Databases
External APIs
Development environments
```

Không phải server nào cũng cần hoạt động trong mọi phiên làm việc.

Việc kiểm soát startup giúp developer giảm phạm vi hoạt động của agent.

Đây là một cách tiếp cận phù hợp với nguyên tắc least privilege.

### AI evaluation cần nhiều hơn một câu trả lời hợp lý

AWS DevOps Agent Reviews cho thấy một vấn đề đáng quan tâm.

Một AI agent có thể đưa ra kết luận nghe thuyết phục.

Nhưng developer vẫn cần biết:

```plaintext
Is the conclusion grounded in evidence?

Did the agent investigate the right scope?

Was important information missed?

Is the proposed action safe?
```

Đó là lý do evaluation cần được thiết kế thành một bước riêng trong workflow.

### Database security cần hiểu hành vi, không chỉ quyền truy cập

GuardDuty RDS Protection cho thấy hướng phát triển quan trọng của database security.

Một attacker có thể sử dụng credentials hợp lệ.

Khi đó, authentication logs không nhất thiết phát hiện được vấn đề.

Behavioral analysis có thể giúp nhận diện những truy vấn bất thường.

Tuy nhiên, anomaly detection cũng có thể tạo false positives.

Developer cần kết hợp nhiều nguồn evidence trước khi kết luận có tấn công.

### Chi phí AI cần gắn với giá trị thực tế

Khả năng phân tích Bedrock costs theo model là một cải tiến đáng chú ý.

Một ứng dụng có thể sử dụng model lớn cho reasoning, model nhỏ cho classification và một model khác cho embeddings.

Nếu chỉ theo dõi tổng chi phí, developer khó tối ưu.

Một cách đánh giá hữu ích hơn là:

```plaintext
Total AI cost
    /
Successfully completed tasks
```

Chỉ số này không thay thế những metrics khác, nhưng giúp liên kết chi phí với kết quả kinh doanh.
